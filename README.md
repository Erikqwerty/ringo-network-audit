# Сетевой аудит Ringo MDM

Скрипты проверяют две вещи:

1. **Сервер Ringo MDM** правильно настроен за прокси: устройства и агенты до него достучатся.
2. **Сеть** пропускает трафик Apple, без которого MDM не работает.

На выходе — HTML-отчёт, который можно отдать клиенту.

> **Неофициальный проект.** Личный инструмент автора, не связан с разработчиком Ringo MDM.
> Использует только то, что описано в открытой документации ([docs.ringomdm.ru](https://docs.ringomdm.ru)).
> «Ringo» — товарный знак своего владельца.

## Как запустить

```bash
./audit.sh                                 # меню с вопросами
./audit.sh --full https://mdm.example.com  # проверить всё сразу (2–3 минуты)
```

Когда проверка закончится, откроется отчёт. Он лежит в папке `results/<домен>_<дата>_<время>/report.html`.
У каждой строки отчёта есть кнопка «Подробнее»: там видно, какая команда выполнялась и что ответил сервер.

Другие варианты:

```bash
./audit.sh --ringo https://mdm.example.com             # только сервер Ringo
./audit.sh --ringo https://mdm.example.com --internal  # то же, но из внутренней сети
./audit.sh --apple                                     # только доступ к Apple
./audit.sh --watch https://mdm.example.com             # наблюдать за сервером до Ctrl-C
./audit.sh --diff results/<папка A> results/<папка B>  # сравнить два запуска: только различия
./audit.sh --rebuild results/<папка>                   # пересобрать отчёт без новых проверок
./audit.sh --help                                      # все параметры
```

У каждого замечания (WARN) и проблемы (FAIL) в отчёте есть «Что делать»: что поменять и где.

### Запуск у клиента одним файлом

```bash
./tools/bundle.sh          # соберёт dist/ringo-audit.sh
```

Отправьте клиенту `dist/ringo-audit.sh`. Он запускает `bash ringo-audit.sh --full https://…` у себя в сети,
а в ответ присылает архив `ringo-audit_<домен>_<дата>.tar.gz`, который появится рядом. Клонировать репозиторий
клиенту не нужно. Снимки swagger в файл не попадают; добавить их можно флагом `--with-schemas`.

## Что проверяется

### Сервер Ringo

- Путь до сервера:
  - DNS изнутри и снаружи: совпадает ли ответ системного резолвера с публичными DNS.
  - Узлы: если у имени несколько адресов, каждый проверяется отдельно (сертификат, коды ответов).
  - Часы этого компьютера и сервера.
  - MTU: проходят ли большие пакеты в обе стороны. Если передача встаёт, подбирается рабочий размер.
- HTTPS: TLS 1.2 и 1.3, сертификат и цепочка сертификатов, срок действия.
- Все адреса, к которым обращаются устройства и агенты, доходят до Ringo.
- Websocket агента; с `--ws-hold` — не рвёт ли его прокси, если соединение держать долго.
- Не блокирует ли WAF настоящие запросы устройств.
- Нет ли вмешательства провайдера (DPI / ТСПУ) — с параметром `--dpi`.

### Сеть до Apple

- Push-уведомления (APNs), активация устройств, ADE и Apple Business.
- Проверка сертификатов (OCSP / CRL), точное время (NTP).
- Нет ли подмены сертификатов (SSL-inspection) на прокси или файрволе.

### Мониторинг

Постоянно пингует адреса и показывает задержки и потери, как `mtr`.
Режим `--watch` следит только за Ringo: ключевые адреса раз в 10 секунд и постоянно открытый websocket агента.
В журнал попадает каждый разрыв, код ответа и IP узла, который ответил. Так ловятся плавающие проблемы:
обрывы по ночам, один плохой узел за балансировщиком, таймауты прокси.

## Полезные параметры

| Параметр | Что делает |
| --- | --- |
| `--internal` | запуск из внутренней сети: веб-интерфейс должен открываться |
| `--dpi` | искать вмешательство провайдера |
| `--capture en0` | записать трафик во время проверки (нужен sudo) |
| `--compare results/<папка>` | сравнить с прошлым аудитом, например с рабочим сервером |
| `--ws-hold 120` | держать websocket агента 120 секунд (в `--full` включено) |
| `--archive` | упаковать папку результата в `.tar.gz`, чтобы переслать |
| `--no-waf-probe` | не отправлять тестовые строки, похожие на атаки |
| `RINGO_TOKEN=<токен>` | узнать точную версию Ringo (токен не попадает в отчёт) |

## Что нужно

macOS или Linux, `bash`, `curl`, `openssl`, `perl`.
Желательно ещё `dig`, `nc`, `python3`, `tcpdump`: без них часть проверок пропускается.
Без `python3` не работают удержание websocket и подбор MSS.

## Безопасность

- Проверки ничего не меняют на сервере: тестовые данные заведомо неверные, Ringo их отклоняет.
- Запускайте только на серверах, которые вам разрешили проверять.
- В `results/` попадают данные серверов клиентов. Эта папка не добавляется в git — не меняйте это.
- Скрипты предоставляются «как есть», без гарантий.

## Как устроен проект

```text
audit.sh            запуск и меню
modules/ringo/      проверки сервера Ringo
modules/apple/      проверки доступа к Apple
modules/monitor/    мониторинг
report/             сборка HTML-отчёта и сравнения (--diff)
schemas/            описания API Ringo разных версий
lib/remedies.tsv    «Что делать» для каждого замечания
tools/bundle.sh     сборка одним файлом для запуска у клиента
tests/              самопроверка: ./tests/run.sh
```

Каждая проверка — отдельный файл. Файлы сгруппированы в папки по разделам отчёта:

```text
modules/ringo/checks/
  00_header/         шапка отчёта: адрес, IP, версия Ringo
  10_tls/            HTTPS и сертификат
  15_path/           путь до сервера: DNS, узлы, часы, MTU
  20_endpoints/      адреса Ringo
  30_socketio/       websocket агента
  40_waf/            реакция WAF на тестовые строки
  50_device_bodies/  запросы устройств через WAF
  60_dpi/            вмешательство провайдера
  70_fingerprint/    какой прокси, CDN и WAF стоят перед сервером
  75_ws_hold/        итог удержания websocket (--ws-hold)
  80_pcap/           разбор записанного трафика
  90_compare/        сравнение с прошлым аудитом
  99_summary/        итог
```

В начале каждого файла написано, что он проверяет и когда ставит OK, WARN или FAIL.
Проверки выполняются по порядку номеров. Чтобы добавить новую, создайте файл с нужным номером
в подходящей папке. Соглашения для доработки — в [CLAUDE.md](CLAUDE.md).

## Версии Ringo

В разных версиях Ringo разный набор адресов. Скрипт берёт описание API (swagger) с сервера.
Если сервер его не отдаёт, скрипт угадывает версию и берёт описание из `schemas/`.
Новые описания сохраняются туда сами. Если в «Подробнее» написано «код не описан»,
добавьте пояснение в `schemas/known_responses.tsv`.
